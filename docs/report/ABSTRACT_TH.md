# บทคัดย่อ

การบริหารจัดการโครงสร้างพื้นฐานเทคโนโลยีสารสนเทศในเครือข่ายองค์กรที่มีการแบ่งส่วนการเชื่อมต่อ มักประสบปัญหาความกระจัดกระจายของอุปกรณ์ประมวลผล สภาพแวดล้อมเครือข่ายที่มีการแยกขาด (Air-gapped Network) และข้อมูลการทำงานของระบบที่กระจัดกระจาย เมื่อเกิดความขัดข้องขึ้นบนอุปกรณ์ปลายทางที่ไม่มีการติดตั้งโปรแกรมตรวจติดตามแบบต่อเนื่อง ผู้ดูแลระบบจำเป็นต้องแก้ไขปัญหาแบบเฉพาะหน้า ซึ่งใช้ระยะเวลานานและขาดความสามารถในการตรวจสอบย้อนกลับ โครงงานนี้นำเสนอระบบบริหารจัดการโครงสร้างพื้นฐานองค์กร (Enterprise Infrastructure Management System: EIMS) ซึ่งเป็นแพลตฟอร์มบริหารจัดการข้อมูลหลักฐานด้านโครงสร้างพื้นฐานและการวิเคราะห์เพื่อสนับสนุนการตรวจสอบด้วยปัญญาประดิษฐ์ (AI-assisted Investigation) ที่ออกแบบขึ้นเพื่อผสานการทำงานระหว่างเครือข่ายหลักและอุปกรณ์ปลายทางที่ไม่ได้เชื่อมต่อเครือข่าย ระบบ EIMS ทำงานร่วมกันระหว่างทะเบียนทรัพย์สินโครงสร้างพื้นฐานบนฐานข้อมูล PostgreSQL และชุดโปรแกรมรวบรวมข้อมูลหลักฐานแบบพกพาที่พัฒนาขึ้นบน CPython 3.14.3 ชนิดฝังตัว (Embedded Runtime) โดยชุดรวบรวมข้อมูลจะเรียกค้นข้อมูลระบบด้วย Windows Management Instrumentation (WMI) แบบไม่รบกวนการทำงานของระบบ และคัดกรองข้อมูลเหตุการณ์ของระบบ Windows เฉพาะช่องทาง System และ Application ในกรอบเวลา 24 ชั่วโมง โดยกำหนดขีดจำกัดเริ่มต้นไว้ที่ 500 เหตุการณ์สำหรับการสืบค้นรวม จัดเก็บเป็นแฟ้มข้อมูล JSON ออฟไลน์ที่มีการตรวจสอบโครงสร้างข้อมูลอย่างรัดกุม เมื่อนำเข้าข้อมูลสู่ส่วนกลาง ระบบจะดำเนินการตรวจสอบข้อมูลซ้ำในระดับแอปพลิเคชันสำหรับการนำเข้าทีละชุดด้วยการสร้างค่าแฮช SHA-256 ของแต่ละเหตุการณ์ พร้อมทั้งจัดลำดับความสำคัญตามระดับความรุนแรง ในขั้นตอนการวิเคราะห์เพื่อช่วยสนับสนุนการวินิจฉัยปัญหาของเจ้าหน้าที่ ตัววิเคราะห์ปัญญาประดิษฐ์จะถูกจำกัดขอบเขตการทำงานไว้ที่ไม่เกิน 10 รายการต่อรอบการนำเข้า โดยประยุกต์ใช้เวกเตอร์การฝังความหมายของข้อความ (FastEmbed `BAAI/bge-small-en-v1.5` ร่วมกับ SentenceTransformer `all-MiniLM-L6-v2` สำรอง) ร่วมกับสถาปัตยกรรมการสืบค้นเสริมการสร้างข้อความ (RAG) และบันทึกผลการวินิจฉัยเป็นประวัติผลการวิเคราะห์ (AnalysisHistory) ที่เชื่อมโยงย้อนกลับไปยังทรัพย์สินนั้น การประเมินผลระบบครอบคลุมชุดการทดสอบอัตโนมัติ การนำเข้าข้อมูลภาคสนามในอดีต และการตรวจสอบความถูกต้องของขั้นตอนหลังการนำเข้าข้อมูล โดยชุดการทดสอบการนำเข้าข้อมูลแบบแยกส่วนของ Sprint 13 ผ่านการทดสอบ 37 รายการ (ล้มเหลว 0 รายการ คำเตือน 4 รายการ) ส่วนต่อประสานผู้ใช้ผ่านการตรวจสอบชนิดข้อมูลของ TypeScript และการสร้างแพ็กเกจสำหรับใช้งานจริง ชุดข้อมูลภาคสนามยืนยันการจัดเก็บข้อมูลเหตุการณ์ของระบบ Windows จำนวน 49 รายการ (System 34 รายการ, Application 15 รายการ) และมีการบันทึกประวัติผลการวิเคราะห์ 10 รายการสำหรับเครื่องเป้าหมาย (`ASSET-01`) ส่วนต่อประสานโปรแกรมประยุกต์ (API) สำหรับคัดกรองประวัติการวิเคราะห์ตอบสนองด้วยรหัสสถานะ HTTP 200 และสามารถแสดงข้อมูลเหตุการณ์และผลการวิเคราะห์บนหน้าเว็บได้ตามที่ทดสอบ (A9 PASS) ทั้งนี้ การทดสอบภาคสนามก่อนหน้าได้พิสูจน์กระบวนการเก็บรวบรวมข้อมูลด้วยอุปกรณ์พกพาและการนำเข้าข้อมูลตามลำดับ ในขณะที่การตรวจสอบหน้างานครั้งล่าสุดเป็นการยืนยันความถูกต้องของการจัดเก็บข้อมูลหลักฐานในฐานข้อมูล ประวัติการวิเคราะห์ การตอบสนองของ API แบบคัดกรอง และการแสดงผลบนเว็บเบราว์เซอร์ ระบบ EIMS แสดงให้เห็นถึงความเป็นไปได้ทางวิศวกรรมในการบริหารจัดการข้อมูลหลักฐานที่สามารถตรวจสอบย้อนกลับได้ และการวิเคราะห์สนับสนุนด้วยปัญญาประดิษฐ์สำหรับระบบออฟไลน์ ภายใต้ขอบเขตการเป็นระบบต้นแบบเชิงวิศวกรรมสำหรับรายงานสหกิจศึกษา ซึ่งมีความแตกต่างจากระบบเชิงพาณิชย์สำหรับสภาพแวดล้อมการผลิตจริงหรือระบบนิติวิทยาศาสตร์ดิจิทัล

**คำสำคัญ:** ระบบบริหารจัดการโครงสร้างพื้นฐานองค์กร, ข้อมูลหลักฐานด้านโครงสร้างพื้นฐาน, บันทึกเหตุการณ์ระบบ Windows, การรวบรวมข้อมูลหลักฐานแบบออฟไลน์, การวิเคราะห์เพื่อสนับสนุนการตรวจสอบด้วยปัญญาประดิษฐ์, การจัดการทรัพย์สิน, การสังเกตการณ์ระบบ
