## Secure-mode fail-closed decisions (three websocket/history tests)
Removed condition 1: `ws_controller` refused every connection when `AUTH_MODE != demo`. It was a login dependency **plus** an unrelated gap: the handler had (and after the product change had) no Origin check at all. Decision: **restored as an independent boundary, explicitly mode-scoped**. `websocket_origin_refusal`: an `Origin`, if present, must equal an entry of `CORS_ORIGINS` (scheme+host+port; `*`, `null`, empty list never match; unreadable headers refuse); a missing Origin (non-browser client) is accepted in default/local mode and refused when `AUTH_MODE=secure`. Refusal happens before `accept()`. Tests: untrusted/look-alike/null/`*` origins rejected in both modes (before registration), configured local origins accepted without any login, missing-Origin matrix, empty/wildcard allowlist fails closed, real ASGI handshake accept and deny.
Removed conditions 2 and 3: `vector_db.add_solution` / `search_similar_logs` returned nothing in secure mode ("shared vector rows have no owner"). Independent data-ownership boundary, not a login dependency: **restored** (secure mode never publishes History into, or reads from, the ownerless vector namespace; default mode unchanged). The unmodified original test passes again. Approved Knowledge (`knowledge_entries`) is unaffected and still served in all modes.
