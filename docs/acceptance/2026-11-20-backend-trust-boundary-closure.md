## P0-2 Correlation time semantics (done, with a product-level consequence)
* New clocks: `event_time` (parsed only from source fields with known semantics), `ingested_at` (= `incident_evidence.created_at`), legacy `observed_at`; plus `time_basis`, `time_confidence` (`exact | asserted | ambiguous | missing`), `time_original` (verbatim). Module `incident/event_time.py`.
* Rules: explicit UTC/offset => exact; local time with an explicitly declared zone => exact; caller-supplied tz-aware structured timestamp => asserted; naive/zone-less local time, day/month-ambiguous (`11/20/2026 9:14 AM`), time-of-day only, date only, future (> 5 min skew) => ambiguous; malformed/absent/absurd offset => missing. No zone guessed, no date inferred. IANA zone names need `tzdata` (absent on this Windows host; such names then degrade safely to ambiguous, 2 tests skip).
* Correlation: only `exact`/`asserted` event time takes part. Strong merge needs same registered asset + same provider-qualified signature + both event times trustworthy and inside the window + open incident. Without trustworthy time: separate incident, `ambiguous_not_merged`, same-asset/same-signature incidents listed as candidates (`event_time_untrusted:<basis>`). The dedupe key is bound to the source record whenever the asset or the event time is untrusted, so ingestion proximity cannot merge through the key either. `summary.correlation.time` records basis/confidence/original and `ingestion_time_is_not_event_time`.
* **Consequence to know:** raw Windows Event Viewer text (`Date: 11/20/2026 9:14:22 AM`) carries no zone and an unclear day/month order, so pasted logs of that form are never auto-correlated by time; they become separate incidents with candidates. Auto-correlation works for XML/ISO/JSON sources with explicit offsets or collectors that supply tz-aware time.
* Regression matrix `tests/test_incident_event_time_pg.py` (parametrised parser rules + 12 integration cases): close events ingested hours apart => merge; far-apart events ingested together => not merged; out-of-order (identity suite test 09); missing timestamp => ambiguous; malformed => marked, not merged; explicit UTC / offset / declared-zone agree; ambiguous local => not merged; future => untrusted; repeated event => idempotent; unregistered asset => never merges; legacy direct callers => asserted; coarse time text never fingerprints; absurd offsets => malformed, no 500.
* Test contract changes (not weakenings): identity suite `hist` rows now carry an explicit UTC event time (`untimed=True` for the negative cases); test 08 now asserts the stricter outcome (two incidents, no fingerprint, `ambiguous_not_merged`); `_analysis` helper in the event-link test got a timestamp and unique text; consumer unit-test fake gained a pass-through `enrich_evidence` and asserts it is called.
